# 보고서 양식

두 출력물의 정확한 양식. 섹션 구성과 표 컬럼은 그대로 따르고, 내용은 프로젝트에 맞게 채운다.
양식을 지켜야 하는 이유: `fix` 모드와 이후 세션이 이 구조를 전제로 항목을 찾고 상태를
갱신하기 때문이다. 컬럼을 빼거나 상태 표기를 바꾸면 재개가 깨진다.

상태 어휘 (이 네 가지만 사용):
`미처리` / `완료 (YYYY-MM-DD)` / `보류 — 사유` / `무시 — 사유`

작업량: `S`(30분 내) / `M`(반나절) / `L`(하루 이상)

---

## 2. 총괄 로드맵: `ROADMAP.md` (프로젝트 루트)

```markdown
# <프로젝트명> 로드맵

> 이 프로젝트의 단일 기준 로드맵. 산재해 있던 계획 문서를 통합한 것으로,
> 원본은 docs/roadmap-archive/ 에 보존되어 있다.
> 최종 갱신: YYYY-MM-DD

## 1. 프로젝트 목표
<목적 요약 2~3문장>

## 2. 지난 진행 기록

<시간순. 완료 표기: ✅ 검증됨(코드/git으로 확인) / ☑️ 문서상 완료(검증 불가)>

### <시기: 예. 2025 상반기>
- ✅ 2025-03 — <완료된 일> (근거: 커밋 abc1234 | 파일 src/x.py)
- ☑️ 2025-05 — <문서상 완료이나 코드로 확인 못한 일> (출처: plan-v1.md)

## 3. 향후 로드맵

<우선순위와 의존 순서대로. 각 항목에 출처(원본 문서 또는 감사 제안 ID)를 남긴다>

### 단기 (지금 ~ 1개월)
- [ ] <항목> — 출처: <원본 문서명 | 감사 P-03>
### 중기 (1~3개월)
- [ ] 
### 장기 / 아이디어
- [ ] 
### 폐기됨
- ~~<더 이상 유효하지 않은 옛 계획>~~ — 사유:

## 4. 편입 이력
| 원본 파일 | 처리 | 현재 위치 |
|-----------|------|-----------|
| docs/plan-v2.md | 편입 후 아카이브 (YYYY-MM-DD) | docs/roadmap-archive/plan-v2.md |
| README.md의 "향후 계획" 섹션 | 편입, 원본은 링크로 교체 | - |
```

시기 구분(단기/중기/장기)의 기간은 프로젝트 속도에 맞게 조정해도 된다. 다만 "무엇이
먼저이고 무엇이 무엇에 의존하는가"가 드러나는 시간 순서 배열은 유지한다.
