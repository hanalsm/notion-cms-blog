# 로드맵 통합 절차 (Phase 4)

여러 곳에 흩어진 로드맵·계획 문서를 하나의 총괄 `ROADMAP.md`로 통합한다. 결과물 양식은
`references/templates.md`의 2번 양식을 따른다.

## 1. 후보 수집

Phase 1의 문서 인벤토리에 더해, 다음 패턴으로 빠짐없이 검색한다:

- 파일명: `ROADMAP*`, `TODO*`, `PLAN*`, `MILESTONE*`, `BACKLOG*`, `*roadmap*`, `*plan*`,
  `*todo*` (대소문자 무시)
- 한국어 파일명: `*로드맵*`, `*계획*`, `*할일*`, `*일정*`, `*진행*`
- 위치: 프로젝트 루트, `docs/`, `.claude/`, `notes/`, 위키성 폴더
- 파일 전체가 아니라 **문서 안의 로드맵 섹션**(README의 "향후 계획", CLAUDE.md의 TODO 등)도
  후보에 포함한다.

각 후보의 최종 수정 시점을 기록한다(`git log -1 --format=%ci -- <파일>`). 문서 간 내용이
충돌할 때 "어느 쪽이 최신인가"를 판단할 근거가 된다.

## 2. 파싱

문서별로 항목을 추출한다: `{내용, 상태(완료/진행중/계획), 시기 단서, 출처 문서}`.
체크박스(`[x]`), 취소선, "done", "완료", 이모지 등 표기가 문서마다 제각각이므로 형식이
아니라 문맥으로 판단한다. 시기 단서(날짜, "다음 주", 버전 번호)도 있으면 함께 추출한다.

## 3. 완료 주장 검증

**"완료"로 표시된 항목을 그대로 믿지 않는다.** 로드맵 문서는 실제 진행과 자주 어긋난다 —
완료됐는데 표시가 안 된 것도, 표시만 되고 실제론 안 된 것도 흔하다. 어긋난 기록을 그대로
옮기면 통합본의 신뢰가 무너지고, 이 통합 작업 자체가 무의미해진다.

- git 히스토리에서 해당 기능의 커밋을 찾는다: `git log --oneline --all -i --grep="<키워드>"`
- 해당 기능의 코드/파일이 실제로 존재하는지 확인한다.
- 결과 표기:
  - ✅ 검증됨 — 코드나 커밋으로 확인함 (근거를 병기)
  - ☑️ 문서상 완료 — 확인할 방법이 없거나 확인 못함
  - ⚠️ 불일치 — 완료 표시인데 코드에 없음 → 로드맵의 "향후" 쪽으로 되돌리고 그 사실을 명기
- 반대 방향도 본다: git 연혁에는 있는데 어떤 로드맵에도 없는 굵직한 작업은 "지난 진행
  기록"에 추가한다 (근거: 커밋).
- 항목이 아주 많으면(50개+) 전수 검증 대신 핵심 항목 위주로 검증하고, 나머지는 ☑️로 두되
  그 기준을 편입 이력에 적는다.

## 4. 병합 규칙

- 같은 항목이 여러 문서에 있으면 하나로 합치고 출처를 병기한다.
- 문서 간 충돌(한쪽은 완료, 한쪽은 계획)은 검증 결과가 우선. 검증 불가면 최신 문서를
  따르고 각주로 충돌 사실을 남긴다.
- 버려진 것으로 보이는 옛 계획은 조용히 삭제하지 않는다 — "장기/아이디어" 또는 "폐기됨"
  섹션에 사유와 함께 보존한다. 사용자가 잊고 있던 계획을 되살릴 기회가 된다.
- 이번 감사에서 사용자가 채택한 개선 제안(P-xx)은 향후 계획의 적절한 시기에 편입한다.

## 5. 작성과 아카이브

1. templates.md 양식으로 `ROADMAP.md`를 작성한다. 기존 `ROADMAP.md`가 이미 총괄본
   역할을 하고 있으면 재작성하지 말고 그 위에 검증 결과와 누락분을 반영해 갱신한다.
2. **정지 지점 — 사용자 확인**: 편입한 원본 파일 목록과 이동 계획(무엇을 어디로)을
   보여주고 확인을 받는다. 파일 이동은 사용자의 저장소 구조를 바꾸는 일이다.
3. 확인 후 원본을 `docs/roadmap-archive/`로 이동한다 (git 저장소면 `git mv`). 삭제 금지.
   로드맵 "섹션"만 있던 문서(README 등)는 이동하지 않는다 — 해당 섹션을 `ROADMAP.md`
   링크로 교체할지 사용자에게 함께 묻는다.
4. 이동한 파일을 가리키던 다른 문서의 링크가 있으면 갱신한다 (grep으로 파일명 검색).

## 엣지 케이스

- **로드맵 문서가 0개**: git 연혁 + 감사 결과 + 채택된 제안으로 첫 로드맵을 만들고,
  "기존 계획 문서 없이 새로 작성함"을 명시한다.
- **이미 단일하고 잘 정리된 로드맵이 있음**: 통합할 게 없으면 검증(3번)과 과거 기록 보강,
  양식 정리만 제안한다. 멀쩡한 문서를 뒤엎지 않는다.
- **진행 기록이 어디에도 없음**: git 마일스톤만으로 "지난 진행 기록"을 재구성한다.
